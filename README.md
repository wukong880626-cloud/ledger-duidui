# 台账对对看 · 本地原型 0.1.1

**[在线试用](https://wukong880626-cloud.github.io/ledger-duidui/)** · [源代码](https://github.com/wukong880626-cloud/ledger-duidui) · [构建与部署状态](https://github.com/wukong880626-cloud/ledger-duidui/actions/workflows/pages.yml)

用于两份房地产或通用明细台账的精确核对。数据仅在浏览器和本机计算线程内处理，无上传、遥测、AI API、运行时 CDN 或账号。开发与测试只使用合成数据。第二轮已修复导入耗时、重复说明膨胀、数值精度与特殊文本保真问题，详见 `第二轮验收_v0.1.1.md`。

应用不上传台账，不等于托管平台没有访问日志。在线首次加载需联网，GitHub Pages 会为安全目的记录访问者 IP，详见 [隐私说明](PRIVACY.md)。发布状态和待验收项见 [发布验收](发布验收.md)。

## 普通使用者启动

1. 解压完整 ZIP，保留 `dist` 中的文件在同一目录。
2. 本机 macOS 已装 Node.js 时，可双击 `启动台账对对看.command`；它会分配空闲的本机端口并打开默认浏览器。保留终端窗口，按 Ctrl+C 停止。启动脚本的 Finder 双击行为未做人工验收。
3. **已验证的启动方式**：电脑已安装 Node.js 20 或以上时，在项目目录运行 `npm start`，用近期 Chrome 打开 **http://127.0.0.1:4173**。仅监听本机；按 Ctrl+C 停止。不需要 `npm install` 就能启动已经打包的页面。端口占用时可运行 `PORT=4174 npm start`。
   0.1.1 使用随包附带的本机计算线程，**须使用本机 HTTP 入口**。直接双击 `dist/index.html` 不属于支持的启动方式。“打开台账对对看.html”提供启动提示，不会把文件上传到服务器。
4. 点击“试用合成示例”，再点击“开始核对”，先熟悉异常及追溯方式。

不要在浏览器隐私扩展、录屏或远程协助正在采集页面时导入敏感台账。应用本身不保存数据；关闭或刷新页面会清除本次数据，导出的报告由使用者自行保管。

## 核对步骤

1. 在 A、B 两边各选一份 `.xlsx` 或 `.csv`。XLSX 再各选一个工作表和标题行。仅支持单行标题，不支持标题/数据区域合并；标题之前的说明行允许合并。
2. CSV 默认 UTF-8，解码失败可切换 GB18030 后重读。同一 CSV 内仅一张表。逗号、分号、制表符根据第一条记录判断；如有说明行，请确保分隔符与正文相同。
3. 按预览确认标题。CSV 标题选择按“记录序号”，预览及报告行号为该记录起始的物理行号；引号内跨行文本不会使追溯错位。
4. 手动选择每个主键分量的 A/B 列，点击“添加主键”可以组合“楼栋＋单元＋房号”。每个分量逐字匹配，保留大小写、首尾空格及前导零。不拼接成易碰撞的简单字符串，不做模糊匹配。
5. 选择状态/文本或金额核对字段，分别指定两边的列。金额单位必须明确选择“元、千元、万元、亿元”，比较前统一为元。默认容差 0.01 元，可改为非负数。
6. 点击“开始核对”，查看差异明细和重复/无效记录。可以搜索、分页。字段或源表设置有变化时，旧结果立即失效，须重新核对。
7. 点击“导出 XLSX 报告”，下载独立报告。报告包含“概览、差异明细、重复与无效记录”，不写回原表。

## 结果口径

- 状态/文本逐字比较。金额使用十进制运算，绝对差额 **≤** 容差视为相同；差额符号为 **A−B**，单位元。两边金额都空白可以一致；一边空白另一边为 0 会报告异常。
- 只核对已映射的字段，不代表整份文件全部列一致。只有存在有效配对、无差异且无待处理记录，才显示“所选字段全部一致”。
- 空键、缺少复合键分量、重复键、非法金额、Excel 错误值和关键字段公式单列。某键出现重复或无效核对字段，该键两侧均隔离，不强行配对或误报对侧缺项。
- 无法得到合法主键的记录（如空键、缺分量、公式主键）无法关联对侧；对侧独有记录仍按其有效键列出，并提示结合待处理记录核查。
- 关键字段有公式时，无论是否有缓存均提示在**原表副本**中粘贴为值并重导；不重算公式，不把无缓存公式当零。原生 CSV 中以 `=` 开头的内容按普通文本处理，不执行。
- 金额接受数字、小数点、正负号及规范千位逗号；币种符号、括号负数和科学计数法文本须先整理。首版最多 40 位数字、12 位小数。
- 数字编号可保留 XLSX 中已有补零格式（如 `0000`）；源文件已丢失的前导零或精度无法恢复。建议编号列在来源文件中保持文本；数值型主键为负数、非整数或超出 JS 安全整数时隔离。
- XLSX 会先检查原始数值 XML；超过 15 位有效数字或存在读取舍入风险的关键数值将隔离，并保留 XML 中原值。高精度金额请在来源中核实后使用文本数值；不能把已经舍入的数字自动恢复。
- 金额原值和差额在报告中按文本保存，防止再次发生精度转换。危险文本前置单引号并以字符串写入；报告不含公式、宏或外部链接。该防护前缀会显示在某些读取工具中。
- 特殊文本如 `_x0041_`、嵌套转义序列会保真写入。不能无损写入 XLSX 的控制字符和超长文本明确拒绝，不静默删改。重复组说明仅预览前 20 个行号，但每条重复记录的原始行号仍逐条完整保留。
- “差异明细条数”按字段异常计数，“有差异配对”按有效配对记录计数，“待处理源记录”按每侧原始行去重。一个源记录可能有多个待处理事项。

## 合成样本

`samples/` 内文件均为新造数据：

- `异常示例_A.xlsx` / `异常示例_B.xlsx`：选择“销售明细”，A 标题第 2 行、B 标题第 1 行。CSV 版本使用相同数据。主键与金额映射见下表。
- `一致示例_A.csv` / `一致示例_B.csv`：单主键、行列顺序及标题不同，但所选字段完全一致。
- `公式拦截示例.xlsx`：含无缓存金额公式、有缓存状态公式及无缓存主键公式。
- `解析失败示例.csv`：引号未闭合，必须拦截。
- `公式对侧示例.csv`、`分页示例_A/B.csv`、`安全文本_A/B.csv`：用于公式隔离、121 条差异分页与恶意文本防护验收。
- `预期核对报告.xlsx` / `预期结果.json`：异常示例的可复核预期结果。
- `第二轮/`：数值精度风险、特殊文本、控制字符及 UTF-8/GB18030 编码合成样本。

| 字段 | A 列 | B 列 | 核对方式 |
|---|---|---|---|
| 楼栋 | 楼栋 | 楼号 | 主键 1 |
| 单元 | 单元 | 单元号 | 主键 2 |
| 房号 | 房号 | 房间编号 | 主键 3 |
| 销售状态 | 销售状态 | 状态 | 状态/文本 |
| 合同金额 | 合同金额（元） | 合同总价（万元） | A 元 / B 万元 |

默认容差 0.01 元时：A 13 条、B 10 条；有效配对 7 对，其中 3 对一致、4 对有差异；仅 A/仅 B 各 1 条；6 条字段差异；7 条重复/无效明细，涉及 7 条源记录。

一致样本映射：A“编号”↔B“房间编号”作单主键；A“状态”↔B“销售状态”作文本；A“金额（元）”↔B“金额（万元）”作金额，单位分别元、万元。不要忘记删除多余的空映射。

## 开发与验证

源代码在 `src/`，纯逻辑在 `core.js`，文件解析/报告在 `io.js`，本机计算线程在 `worker.js`，限制在 `limits.js`。UI 使用原生 HTML/CSS/JavaScript，本地打包采用 esbuild；XLSX 使用 ExcelJS，十进制运算使用 decimal.js，编号格式使用 SSF，ZIP/XML 预检使用 JSZip/Saxes。所有依赖本地打包，版本锁定在 `package-lock.json`。自有代码按 [MIT](LICENSE) 授权，署名 wukong880626-cloud；第三方仍遵守各自许可，声明在 `dist/THIRD_PARTY_NOTICES.txt` 和 `.LEGAL.txt` 文件中。

```sh
npm ci
npm run samples
npm test
npm run build
npm start
```

保持本机服务运行，在另一个终端执行 `npm run test:browser` 可重复最终 Chrome 回归（需要本机 Chrome 和已安装开发依赖）。浏览器测试脚本仅使用 `samples/` 中的合成文件，并把截图、下载报告与日志保存至 `output/playwright/`。

`npm ci` 仅开发/重建时需要联网。本机模式使用已构建页面无需互联网或安装项目依赖。在线模式首次需取得页面、脚本和 Worker，加载完成后可断外网继续本次计算；关闭或刷新后不保证离线重开。可靠离线启动请使用本机模式。测试覆盖和未测试事项见 `测试结果.md`。

子路径验收可运行 `PORT=4175 LEDGER_BASE_PATH=/ledger-duidui npm start`，访问 `http://127.0.0.1:4175/ledger-duidui/`。公开文件扫描运行 `node scripts/audit-public.mjs`；output、release、缓存、环境文件和凭据目录一律不公开，不要用全目录添加代替白名单审查。

第二轮可重复验收：依次运行 `node scripts/round2-fixtures.mjs`、`node scripts/round2-functional-fixtures.mjs`，保持本机服务后运行 `node scripts/round2-browser-check.mjs`。大表性能脚本为 `scripts/round2-browser-perf.mjs`；全部只使用新造数据。ZIP 不包含可重新生成的大表和其大份导出，包含测量 JSON、日志、小样本和生成脚本。

## 首版限制

建议日常先按每侧 **10,000 条以内**使用。0.1.1 将硬上限保守收紧为：每份 ≤20 MB、≤150,000 个单元格（含标题及全部工作表/读取矩形）；每表 ≤25,000 条明细、200 列；标题/说明最多另占 100 条记录；两侧异常明细总计 ≤25,000 条；最多 8 个主键分量、20 个核对字段，主键单分量 ≤256 字符。

文本每格 ≤32,766 字符；安全转义后仍须满足 XLSX 每格 32,767 字符。XLSX 声明解压体积 ≤50 MB、内部文件 ≤1,000 项、工作表 ≤20 张；不支持 ZIP64/分卷。任何上限触发会明确拒绝，不截取部分结果冒充完整核对。多字段异常可能比原始行数多，因此较小台账也可能达到异常总量上限。

25,000 条/侧、5 列已完成实际 CSV/XLSX 压力验收，但导出期间隔离 Chrome 渲染进程 RSS 采样仍可接近 1 GB，普通电脑应先拆小表。上限不是任意宽表或低内存电脑的性能保证。仅核验声明解压体积，不构成恶意压缩文件安全扫描；不适合压缩炸弹或不可信来源文件。其他工作表超限也会拒绝整个工作簿。

不处理宏、旧版 `.xls`、加密文件、公式重算、复杂多层/合并表头、自动改账、多人账户、后台保存、AI 判断哪份为准或在线部署。未映射字段不核对。浏览器/办公软件兼容性和性能测试范围见测试记录，不应把原型当专业审计结论。
